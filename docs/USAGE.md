# CV Tailor AI - Usage Guide

## Overview

CV Tailor AI automates the process of adapting your CV for specific job opportunities using LLM intelligence.

## Quick Start

### 1. Installation

```bash
git clone <repo-url>
cd cv-tailor-ai-ts
npm install
echo "OPENAI_API_KEY=your-api-key-here" > .env
npm run build
```

### 2. Prepare Your Base CV

The base CV must use the `.content` paragraph layout styled by `shared.css`. Use `original/MR_cv_base.html` as the template:

```
original/
├── MR_cv_base.html    # Primary CV (default in config.yaml and in the web app)
├── cv_template.html   # Empty layout skeleton (web "Blank template")
└── shared.css         # Stylesheet (copied to output on each run)
```

Required HTML patterns:

- Root: `<div class="content">`
- Sections: `<section class="title">PROFESSIONAL SUMMARY</section>`
- Skills: `<p class="competency-item">`
- Experience headers: `<p class="experience-header">`
- Bullets: `<p>• ...</p>`

Deprecated layouts (`cv-container`, `experience-item`, etc.) are rejected at load time and after LLM adaptation.

### 3. Run the Adapter

#### From Text File

```bash
npm start -- --file offers/job_offer.txt
```

#### From URL

```bash
npm start -- --url "https://company.com/careers/frontend-developer"
```

#### From Direct Text

```bash
npm start -- --text "Senior Frontend Developer needed with React experience..."
```

> Note: `--text`, `--file`, and `--url` are mutually exclusive — provide exactly one.

### 4. Get Your Adapted CV

Find your tailored CV in:

```
output/Miguel-Rivero-Lopez-{job-title}.html
output/shared.css
output/Miguel-Rivero-Lopez-{job-title}.pdf   # unless --html-only or pdf.enabled: false
```

Open the HTML in a browser from the `output/` folder so `shared.css` loads correctly.

## Advanced Usage

### Custom Base CV

```bash
npm start -- --file offers/job.txt --base original/custom_cv.html
```

### Framework Emphasis

Use `--framework` to control how framework experience is presented
(`react` | `vue` | `agnostic`, default: `agnostic`):

```bash
# Emphasize quick, confident ramp-up to React (primary experience is Vue)
npm start -- --file offers/job.txt --framework react

# Emphasize Vue experience specifically, without mapping to React
npm start -- --file offers/job.txt --framework vue

# Framework-agnostic: stress general frontend framework experience
npm start -- --file offers/job.txt --framework agnostic
```

The CLI always passes one of these modes. Omitting `--framework` is the same as `agnostic`.

### Web app

```bash
npm run dev:web
```

Open http://127.0.0.1:5180/cv-tailor-ts/.

The React / Vue / Agnostic control appears only for the default CV (`original/MR_cv_base.html`). Choosing **Blank template** or uploading another HTML file hides it. That request omits `framework`. Keyword extraction then leaves `synonyms.Vue_to_React` empty, and adaptation does not add frontend framing or invent tools that are not in the uploaded HTML. The blank file is `original/cv_template.html` (placeholders such as "Your Name", not a copy of the default CV). Upload is HTML in this layout only.

### Custom Output Directory

```bash
npm start -- --file offers/job.txt --output-dir my_cvs
```

### Verbose Mode

```bash
npm start -- --file offers/job.txt --verbose
```

### Skip Watermark Check

```bash
npm start -- --file offers/job.txt --no-watermark-check
```

## Understanding the Process

### Step 1: Keyword Extraction

The system analyzes the job offer and extracts:

- **Hard Skills**: Technical abilities (e.g., TypeScript, Testing)
- **Soft Skills**: Interpersonal abilities (e.g., Leadership, Communication)
- **Technologies**: Tools and frameworks (e.g., React, Docker)
- **Responsibilities**: Key job duties
- **Synonyms**: Framework translations (Vue ↔ React)

### Step 2: Title Extraction

Extracts and normalizes the job title:

- "Senior Frontend Developer" → `senior-frontend-developer`
- "React + TypeScript Engineer" → `react-typescript-engineer`

### Step 3: CV Adaptation

Adapts your CV while:

- ✅ Preserving HTML structure
- ✅ Integrating relevant keywords
- ✅ Translating frameworks (Vue → React)
- ✅ Anonymizing company names
- ✅ Maintaining authenticity

### Step 4: Watermark Removal

Removes any AI-generated traces:

- "Generated by AI" ❌
- "As an AI model" ❌
- "This CV was adapted using" ❌

### Step 5: Structure Validation

Validates the adapted HTML still matches the `shared.css` layout:

- Requires `<div class="content">`
- Rejects deprecated selectors (`cv-container`, `experience-item`, etc.)
- Runs after LLM adaptation and before save

### Step 6: File Generation

Creates the final files:

```
output/Miguel-Rivero-Lopez-{job-title}.html
output/shared.css
output/Miguel-Rivero-Lopez-{job-title}.pdf   # when enabled
```

PDF generation inlines `shared.css` so Puppeteer renders a styled A4 document.

## Configuration

Edit `config.yaml` to customize behavior:

```yaml
model: 'gpt-4o'
temperature: 0.7
base_cv: 'original/MR_cv_base.html'
shared_css: 'original/shared.css'
output_dir: 'output'

pdf:
  enabled: true
  format: 'A4'
```

## Troubleshooting

### "Base CV not found" or structure validation error

Ensure your CV is in `original/` and uses the `.content` layout:

```bash
ls original/MR_cv_base.html
```

If you see a message about deprecated layout, compare your file with `original/cv_template.html`.

### "Shared stylesheet not found"

Check `shared_css` in `config.yaml` points to `original/shared.css`.

### "OpenAI API Error"

Check your API key:

```bash
echo $OPENAI_API_KEY
```

### "Watermarks detected"

Re-run with verbose mode to see detections:

```bash
npm start -- --file offers/job.txt --verbose
```

### "Invalid JSON from keywords extraction"

The LLM response may need cleaning. Check logs and retry.
